## 1. Why Project Knowledge Matters

Traditional software development is plagued by **knowledge erosion**. As developers leave, models switch, or chat histories are cleared, context is lost.

PromptEngine distinguishes between two types of engineering knowledge:
- **PromptEngine Engineering Playbooks**: Teach **HOW to build** (e.g. secure coding, indexing, naming, testing patterns). These are global, reusable, and language-specific.
- **Project Knowledge System**: Defines **WHAT is being built** (e.g. product specifications, database schemas, API contracts, custom business logic). This is local, project-specific, and unique to the application.

### Why Chat History is Temporary
Chat history is ephemeral and volatile. Relying on chat logs to preserve context creates:
- **Model Incompatibility**: Moving to a newer AI model instantly clears previous memory contexts.
- **Token Inflation**: Re-sending massive historical transcripts to explain past choices wastes tokens and introduces logical hallucinations.
- **Developer Handover Friction**: New human developers cannot easily search through private chat loops to understand why an architectural decision was made.

Therefore, **the repository itself must remain the single source of truth**. Every feature design, database relationship, and business rule must reside in version-controlled markdown files within the project codebase.

## 2. Responsibilities

Maintaining project context is a shared discipline:

### AI Agent Responsibilities
- **Reconstruct Context on Boot**: Always read the `AGENTS.md` first before starting work. Load the indexing manifest and required standard playbooks.
- **Auto-Generate AGENTS.md**: On project bootstrap, generate `AGENTS.md` in the project root by copying/filling the `AGENTS.template.md` template.
- **No Speculative Generation**: Never invent business rules, API payloads, or database keys. If information is missing, locate it in code or ask the developer.
- **Incremental Maintenance**: When implementing a feature, update the relevant local documentation files (such as API specifications or ADR decisions) as part of the pull request.

### Human Developer Responsibilities
- **Verify & Commit**: Review and verify the initial `AGENTS.md` and documentation generated by the AI on project startup.
- **Audit AGENTS.md**: Ensure `AGENTS.md` remains accurate as stack details or constraints evolve.
- **Review ADRs**: Review and approve Architecture Decision Records (ADRs) before the AI proceeds with code changes.

## 3. Project Documentation Categories

Every project maintains its AI Constitution at the root, along with ten structured specifications under the local `/docs/` or `.agents/` folder:

### Root Level
- **AGENTS.md**: The project's AI Constitution. Defines the project overview, tech stack, conventions, and exceptions. It is read by AI agents first.

### Specs & Logs Folder (docs/)
1. **PRD (Product Requirements Document)**: Outlines user personas, target features, user stories, and acceptance criteria.
2. **Architecture**: Diagrams service layouts, trust boundaries, third-party integrations, and boundary policies.
3. **Business Rules**: Documents core equations (e.g., tax formulas, interest calculations) and state machines.
4. **Database**: Lists active tables, column indices, relationships, and expand/contract history.
5. **API**: Documents public and private API routes, input payloads, validation rules, and JSON response models.
6. **Decisions (ADR)**: Logs historical architectural options, trade-offs, and final decisions (following the ADR template).
7. **Progress**: A living checklist (`task.md`) tracking feature implementations, bug logs, and testing states.
8. **Roadmap**: Visualizes future scope milestones, technical debt targets, and deprecated modules.
9. **Deployment**: Details CI/CD pipelines, staging setups, secret injection keys, and rollback steps.
10. **Troubleshooting**: Records known log patterns, crash resolutions, and debug scenarios.

## 4. Standard Playbooks

The `project/` module contains the following standards:

- **[Project Bootstrap Standard](01-project-bootstrap-standard.md)**: Instructs AI agents on how to adopt new or existing codebases, detect technology stack boundaries, and establish initial documentation baselines.
- **Documentation Standard (Future)**: Outlines templates and formatting criteria for PRDs, API schemas, and database mappings.
- **Maintenance Standard (Future)**: Guides incremental updates to docs during active feature implementation PRs.
- **Audit Standard (Future)**: Defines checks to locate gaps between the codebase and local documentation.
- **Handover Standard (Future)**: Outlines steps to package project knowledge for developer handovers or model switches.
